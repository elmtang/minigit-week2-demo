# Week 11 Lab: Write the Issues for RepositoryPaths and FileSystem

Today your team plans the work before writing any code: turn the HW7 design of `RepositoryPaths` and `FileSystem` into small GitHub issues. You implement them next session.

**Use:** the HW7 design, Part 2, for *what* to build (exact signatures), and HW8 `issue-drafts/01` to `04` for *how* to write an issue.

## Steps

1. **Break down (30 min).** One behaviour per issue. The first issue of each class creates it and updates `CMakeLists.txt`. Every issue is testable and names the issue it depends on. Aim for about 5 or 6 RepositoryPaths issues and 4 FileSystem issues; put stretch work in its own issue. Show your list to the instructor.
2. **Write (40 min).** One file per issue in `issue-drafts/` (`05-...`, `06-...`) with these sections: Goal, Dependency, Functions to add (exact HW7 signatures), Acceptance criteria, Tests to write (include an error case), Out of scope, Reviewer focus. Add `issue-drafts/README.md` listing number, title, depends on and owner.
3. **Publish (15 min).** Merge all drafts in one PR from the branch `plan-foundation-issues`. Then create one GitHub issue per draft, label it `RepositoryPaths` or `FileSystem`, assign the owner, and link dependencies as `#N`.
4. **Peer review (15 min).** Review another team's issues. Leave at least three comments, then fix the comments on yours.

## Submit

- **Team repository:** the merged `plan-foundation-issues` PR, and labelled, assigned issues.
- **Each student, on the course site:** links to the issues you wrote, and to one review comment you left.
