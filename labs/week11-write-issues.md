# Week 11 Lab: Write the Issues for RepositoryPaths and FileSystem

Today your team plans the work before writing any code: turn the HW7 design of `RepositoryPaths` and `FileSystem` into small GitHub issues. You implement them next session.

**Use:** the HW7 design, Part 2, for *what* to build (exact signatures), and HW8 `issue-drafts/01` to `04` for *how* to write an issue.

## Steps

1. **Set up a shared Google Doc (5 min).** One member creates `Team <N> MiniGit Issues`, shares it with the team (Editor) and the instructor, and adds a table: issue ID, title, depends on, owner.
2. **Break down (25 min).** Fill in the table together. One behaviour per issue. The first issue of each class creates it and updates `CMakeLists.txt`. Every issue is testable and names the issue it depends on. Aim for about 5 or 6 RepositoryPaths issues and 4 FileSystem issues; put stretch work in its own issue. Show the table to the instructor.
3. **Write (35 min).** Each member writes their issues in the same doc, one heading per issue (for example `RP-2 Add headFile() and indexFile()`), with these sections: Goal, Dependency, Functions to add (exact HW7 signatures), Acceptance criteria, Tests to write (include an error case), Out of scope, Reviewer focus. Use Google Docs comments to question each other's issues.
4. **Review and finalize (20 min).** Give another team Commenter access; they leave at least three comments. Discuss as a team, fix every comment, resolve it, and mark each issue **Final**.
5. **Publish on GitHub (15 min).** Copy each final issue into **Issues > New issue**: the heading becomes the title, the sections become the description. Label it `RepositoryPaths` or `FileSystem`, assign the owner, and replace dependency names with links such as `#14`. Tip: turn on **Tools > Preferences > Enable Markdown** in Google Docs, then use **Edit > Copy as Markdown** to keep code formatting.

## Submit

- **Team:** the Google Doc link, and all issues published, labelled and assigned in your repository.
- **Each student, on the course site:** links to the issues you wrote, and to one comment you left on another team's doc.
